NX 3D Viewer

Milestone: 5 — NX Item Structure Panel
Status: Implementation prepared; Siemens NX 1855 workstation verification required
Port: 8888 (fixed)
Launcher: Run.bat

Production changes:
- Removed the floating CURRENT SCENE card and its obsolete DOM and styles.
- Added a left Item Structure panel, with expand/collapse and draggable/keyboard-resizable splitter.
- Model tree uses actual NX Open component occurrences and body names; repeated component instances remain separate nodes.
- Checkboxes toggle rendering of an individual body or an entire component subtree when each NX body exports separately.
- Clicking an item selects it in the tree and displays its name in the status bar.
- NX journal still exports a combined STL, and also produces hierarchy JSON and individual positioned body STLs.
- If any individual body STL cannot be exported, the complete combined STL is retained; tree remains navigable with visibility disabled.
- NX service passes hierarchy path to journal; backend serves registered body STLs and returns tree / geometry mode in /api/open.
- Existing empty scene, loading overlay, camera, wireframe, grid, axes, and fixed port remain.
- Geometry/structure are immediately discarded when starting a new file load; cancel/failure leaves an empty viewer.
- No version/build number shown in the web UI.

Known limits:
- Browser UI checks used a simulated WebGL implementation, not actual 3D rendering.
- NX 1855 and real assembly occurrences must be verified on licensed Windows NX installation.
- NX Open exports STL tessellation rather than exact CAD faces.
- A big assembly may take longer to load because body meshes are exported separately when possible.
- The client enforces 256 MB total STL bytes and 1,000,000 total triangles.
- Structure selection in the tree does not yet highlight the matching geometry in the viewport.
- Siemens .jt and .chr import is not implemented; OPEN NX FILES currently opens .prt only.
- Separate export fallback preserves complete geometry but cannot individually hide/show bodies.
- File picker runs on the computer hosting Python, not the remote browser.
- Existing branch-specific .gitignore files must not be overwritten.

Branch policy:
- Single ZIP for both branches; .gitignore intentionally omitted.
- First extract into dev, test, then commit and push dev.
- Promote only README.md, VERSION.txt, Run.bat, backend/, frontend/, nx/ from dev to main.
- tests/ and dev/ belong only in dev; use selective restore, not a dev -> main merge.

Validation commands (dev branch):
- py -3 -m unittest discover -s tests -v
- node tests/check_stl.mjs
- node tests/check_loading.mjs
- py -3 dev/browser_smoke.py (Chromium and Playwright required)
- Open standalone .prt and an assembly with repeated components on NX 1855.
- Verify: hierarchy names/depth, collapse, splitter, body/component visibility,
  clearing on new load, and complete geometry fallback if a body export fails.
